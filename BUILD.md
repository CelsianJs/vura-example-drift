# Build Drift: real backend anatomy

Cookie namespace: `drift-demo` on HTTP and `__Host-drift-demo` on HTTPS. Host-only cookies are shared across ports. Distinct Harbor/Drift names—not port isolation—avoid local session overwrites; each parser selects only its own token from mixed-cookie headers.

## Walkthrough

Public `/build` is a complete source-linked workshop. Open two tabs of one private workspace → move card → observe committed SSE snapshot → reconnect to authoritative DB state. It renders without a database. Runtime `/source/...txt` links expose only fixed source/documentation files generated by publish-source; env files and symlinks are excluded.

## Framework roles

- `src/pages/index.tsx`: Vura client page; What signals/computed values hold server snapshots/filter/status, never localStorage persistence.
- `src/pages/build.tsx`: static workshop; public HTML/code/source/proof matrix.
- `src/api/health.ts`: Function process/config probe, not storage validation.
- Session/snapshot/items/events: Dedicated routes; process is persistent, disk is not the database.
- External PostgreSQL `drift_demo`: identities/items/audits/shared admission outlive Node.

Cloudflare ingress/R2 static delivery and provider-backed Function/Dedicated execution are distinct. Private SSR/personalized ISR are intentionally absent. Cache invalidation across processes is not claimed.

## Source seams

`security.js` owns exact Origin, HttpOnly cookie, timing-safe CSRF and honest errors. `service.js` recovers expired cookies server-side without reusing the expired workspace. `domain.js` bounds enums/revisions. `store.js` parameterizes SQL through the existing Neon HTTP driver 1.1.0. `_hooks.ts` limits raw/cloned request bytes before Celsian parsing, including chunked whitespace; this compensates locally for Vura 0.8.3 not exposing createApiApp bodyLimit. events.js reserves slots synchronously before async reads and polls committed scoped snapshots.

## Atomicity and bounded admission

PATCH is one conditional UPDATE + audit INSERT CTE statement. Audit failure rolls back both. Stale revision returns 409; matching ceiling version 501 returns 429; unsupported numbers return 422 before PostgreSQL integer conversion. Unknown transport errors report outcome unconfirmed because a server commit can precede a lost response.

Creation calls a fixed schema-scoped SECURITY DEFINER function in `db/002.sql`. It locks a shared admission row, checks disabled/default-closed state, bounds seed count/bytes, purges at most 25 expired workspaces, checks 100 retained/100 successful creations per UTC day, increments that durable counter, and creates workspace/session/items in the same transaction. Function search_path is pg_catalog; tables are fully qualified. PUBLIC EXECUTE is revoked.

Logical session expiry is seven days. Physical cascade deletion runs opportunistically on admitted creation; no deletion deadline is promised when traffic/admission stops. Retained workspace count stays capped at 100; each seed has at most ten items and each item at most 500 audit revisions. Operator-approved cleanup may be added for a strict wall-clock retention policy, never as a public unauthenticated route.

## Least-privilege role contract

Use a fresh isolated demo schema. Migration owner is a separate non-runtime, schema-scoped owner; do not make the app a table/function owner or superuser. After explicitly approving the database, the owner grants the runtime role:

```sql
GRANT USAGE ON SCHEMA drift_demo TO <approved_runtime_role>;
GRANT SELECT ON drift_demo.workspaces, drift_demo.sessions,
  drift_demo.items, drift_demo.events TO <approved_runtime_role>;
GRANT UPDATE ON drift_demo.items TO <approved_runtime_role>;
GRANT DELETE ON drift_demo.workspaces TO <approved_runtime_role>;
GRANT INSERT ON drift_demo.events TO <approved_runtime_role>;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA drift_demo TO <approved_runtime_role>;
GRANT EXECUTE ON FUNCTION drift_demo.create_workspace(uuid,text,text,text,jsonb)
  TO <approved_runtime_role>;
```

Runtime must have **no INSERT on workspaces/sessions/items**, no UPDATE/SELECT on admission, no CREATE/ALTER/DROP, no function ownership or migration-role membership. Otherwise it could bypass or reopen admission. The negative role tests enforce these distinctions against real PostgreSQL.

Only after hosted scope/roles/ingress protection are reviewed may the owner explicitly open admission with `UPDATE drift_demo.admission SET enabled=true WHERE id=1`. This is not an API operation. Migration repeats preserve an existing setting; owner must close admission before unsafe upgrades.

## Migrations

`db/001.sql` defines bounded fresh-schema tables. `002.sql` adds admission/function. `scripts/migrate.mjs` sorts numbered files and batches each file through Neon transaction(array). Explicit statement-breakpoint markers preserve PL/pgSQL body semicolons. ALLOW_DEMO_MIGRATION=yes and separate MIGRATION_DATABASE_URL are required. Owner connection belongs only in owner-controlled ignored `.env.migrate`, loaded by db:migrate; dev/start read only `.env`. Never export owner credentials into the app's shell or save them as runtime Platform secrets. These are fresh-reference migrations, not a certified production/customer-schema upgrade.

## Executable proof

`npm run verify`: Node22 typecheck, eight tests, released-package Vura build and missing-DB HTTP/browser smoke. Real disposable PG17 tests cover denied role bypass, two-client last-slot race, daily UTC rollover, cascade cleanup preserving valid identity, expired-cookie recovery, stale-at-ceiling, 500-mutation cap and committed-response-loss ambiguity. Initial expired-cookie regression failed before the fix.

`npm run smoke:postgres`: actual built runtime + real Neon driver via a test-only loopback transport bridge + browser mutations, two private sessions, 409, full Node restart retaining revision3, two-tab committed SSE. This is not hosted Neon/provider evidence. Missing PG explicitly skips local DB tests; no persistence claim then. Test cluster startup fixes LC_ALL=C for Homebrew PG17 reproducibility.

Static workshop/source and product smoke run at 1480 and 390 widths, check overflow and console errors and save screenshots outside the repository.

## Hosting gates

Database selection/owner approval, schema grants/admission review, runtime-only DATABASE_URL/exact HTTPS APP_ORIGIN, existing Dedicated entitlement, ingress request/read/poll abuse protection, repository publication and actual Vura deployment remain separate. A local DB-backed browser pass is not proof of hosted Neon transport, proxy stream behavior, provider replacement/redeploy persistence, regional failover or backup restoration. Source remains useful while hosting is blocked.
